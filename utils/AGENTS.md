# utils/AGENTS.md

## Role

`utils/` contains developer utilities.

These utilities may help generate schema definitions, inspect reference documents, or perform one-off maintenance tasks.

Utilities are not part of the deep runtime execution path.

## Typical utilities

Examples:

```text
extract_interface_schema_openpyxl.py
generate_schema.py
compare_schema.py
inspect_payload.py
maintenance scripts
```

## Schema extraction role

Schema extraction tools may read external interface documents such as Excel files and generate plain Python schema definitions.

The generated schema should be deterministic.

The generated schema should be usable by:

```text
rm_ref.schema
rm_ref.config
rm_ref.validator
rm_ref.packer
```

## Runtime isolation

Runtime execution should not depend on Excel files.

The intended direction is:

```text
Excel/interface table
  -> utility script
  -> generated Python schema dict
  -> runtime consumes schema dict
```

Do not make core execution import or call Excel parsing utilities.

## Optional dependencies

Utilities may use optional third-party packages when needed.

Examples:

```text
openpyxl
xlrd
```

If a utility needs a third-party dependency, document it clearly.

Do not introduce the dependency into core runtime unless explicitly approved.

## Python compatibility

Prefer Python 3.6-compatible code when practical.

If a utility cannot support Python 3.6 for a good reason, document that limitation at the top of the file.

Core runtime must remain Python 3.6.3-compatible regardless of utility choices.

## Command-line behavior

Utilities may provide command-line interfaces.

A utility CLI should have:

```text
--help
clear input arguments
clear output arguments
non-zero exit code on failure
deterministic output when inputs are the same
```

Avoid hidden hard-coded paths.

Bad:

```text
always read D:\my_private_path\demo.xlsx
```

Good:

```text
--xlsx doc/ref_docs/demo-interface.xlsx
--sheet demo1
--output schema_defs/demo1_v1.py
```

## Generated files

Generated files should include a small header.

Example:

```text
# Auto-generated by utils/extract_interface_schema_openpyxl.py
# Source: doc/ref_docs/demo-interface.xlsx
# Sheet: demo1
# Schema ID: demo1/v1
```

Generated files should be stable enough for Git diff review.

Avoid timestamps in generated output unless explicitly requested, because timestamps make diffs noisy.

## Error handling

Utility errors should be clear.

Examples:

```text
input file not found
worksheet not found
invalid bit range
cannot parse enum description
output path is not writable
```

Avoid swallowing exceptions and producing partial output without warning.

## Forbidden responsibilities

Utilities should not:

```text
run RM algorithms
drive core packet/cell execution
own runtime context classes
modify static config during execution
create hidden global state required by runtime
```

## Tests

Utility tests may live under a focused test directory if needed, such as:

```text
tests/test_schema/
tests/test_integration/
```

Prefer testing pure parsing helpers separately from file-system-heavy CLI behavior.

## Completion checklist

Before finishing a utility task, check:

```text
python <utility> --help
pytest -q tests/test_schema
git diff --name-only
git diff --stat
```

Summarize:

```text
files changed
tests run
known limitations
follow-up needed
```
